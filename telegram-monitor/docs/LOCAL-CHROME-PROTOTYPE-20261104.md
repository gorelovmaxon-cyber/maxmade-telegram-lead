## Что реализовано

`local_chrome.py` держит собственный браузерный процесс и принимает локальные команды из закрытой папки state. Открытие окна само по себе не начинает чтение. `chrome_pilot.py` проводит сверку обоих видимых профилей и запускает только явно запрошенный пилот на600 секунд. Файловый dispatcher — `local_chrome_runtime.py`. Независимый pythonw-процесс запущен отдельно от вычислений чата; устойчивость при закрытии приложения Codex ещё не проверена.

Перед каждым чтением пачки и после её снимка сверяются тот же документ/старые element handles, собственный username, группа, peer, публичная ссылка, участие, доступность сети и положение в конце ленты. Замена/закрытие панели, смена источника/аккаунта, reload, уход вверх по ленте, offline или переполнение отключают приём. В пилоте нужно оставить открытыми Settings слева и профиль группы справа. Это сознательно ограниченный прототип; удобно работать с ним в отдельном окне.

Сначала observer снимает только исходные message IDs и baseline, без текстов старой ленты. Новое добавление должно иметь ID выше baseline и время публикации не раньше начала наблюдения. Повтор отображения отсекается по ID/дате/существующей дедупликации; правка обновляет только уже принятый оригинал с сохранением первоначальной даты и ручного статуса. Старые неизвестные правки не импортируются. Внутренний WebK ID преобразуется в исходный ID; дробные/временные ID запрещены. Ссылка строится только из сверенного публичного username и исходного ID. Автор остаётся неизвестным: программа не угадывает его по соседнему имени или аватару.

Текст идёт прямо в прежний локальный фильтр/SQLite через browser_ingest и monitor.ingest. Для дедупликации сохранён прежний ключ `client:-1001513982592`. Самореклама, партнёрство, вакансии и прямой заказ продолжают различаться прежними правилами. Тексты не направляются агенту/LLM. Новая необязательная область `candidate_ids` в прежней monitor.deliver ограничивает отправку карточками данного пилота; прежние3 pending не отправляются повторно. Схема БД/получатель/кнопки/подпись/ручные статусы сохранены. Постоянный callback-poller в этом прототипе не запускается; ручные статусы доступны прежними локальными командами.

Перед первым ingest создаётся согласованная резервная копия через SQLite backup API. На время пилота берутся прежние reader.lock и monitor.lock: параллельный Telethon-reader или отправитель не допускаются. Начальный getMe проверяет существующий бот; ошибки сети не трактуются как отзыв токена. Автоматической ротации и ввода новых секретов нет.

## Команды продолжения

В PowerShell из `D:\привлечение клиентов\telegram-monitor`; окно уже открыто:

```powershell
.\.venv\Scripts\python.exe local_chrome.py status
# После самостоятельного вступления в группу:
.\.venv\Scripts\python.exe local_chrome.py verify
.\.venv\Scripts\python.exe local_chrome.py profile
.\.venv\Scripts\python.exe local_chrome.py drain
# Только если последние проверки успешны, без JOIN:
.\.venv\Scripts\python.exe local_chrome.py arm
.\.venv\Scripts\python.exe local_chrome.py status
# Прервать раньше лимита:
.\.venv\Scripts\python.exe local_chrome.py stop
```

Если окно было закрыто, сначала запустить отдельный host, затем source→verify→profile→drain→arm. Команда source перезагружает страницу для корректного разрешения username и сбрасывает подтверждение личности; после неё всегда повторять verify/profile.

```powershell
$monitorRoot = (Get-Location).Path
Start-Process -FilePath (Join-Path $monitorRoot '.venv\Scripts\pythonw.exe') -ArgumentList ('"' + (Join-Path $monitorRoot 'local_chrome.py') + '" open') -WorkingDirectory $monitorRoot -WindowStyle Hidden
.\.venv\Scripts\python.exe local_chrome.py source
.\.venv\Scripts\python.exe local_chrome.py verify
.\.venv\Scripts\python.exe local_chrome.py profile
```

Статус содержит только служебные признаки, счётчики, номера карточек и публичные ссылки; .env, cookies, browser storage и содержимое карточек не выводятся. Не запускать прежний `pilot.py start` или `reader.py login`: это исторический маршрут Telethon.

## Приёмка и границы

| Проверка | Фактический результат |
|---|---|
| Настоящий отдельный Chrome/вход | @maxmade_pro подтверждён; вход пережил закрытие/повторное открытие |
| Источник | Username/peer совпали; JOIN — нужно вступление |
| Реальная цепочка новое сообщение→фильтр→Максим | **Не подтверждена**, чтение блокировано до участия |
| Прямой заказ | **Отдельная незавершённая приёмка**; технический ping или партнёрство её не закрывают |
| Тесты | Полный набор100 tests OK; окончательный прогон восстановленной копии и сверка хешей — в соседней .receipt.json кодового пакета |
| Смена личности/peer, замена DOM, JOIN, reload, offline/reconnect | Проверены на изолированных подставных страницах реальным headless Chrome; сеть Telegram перехвачена/не использовалась |
| Сворачивание настоящего окна | Команда выполнена, DOM/связь с host сохранились; окно восстановлено. Получение настоящего события в свёрнутом состоянии **не проверено** |
| Закрытие настоящего Chrome | Вход сохранился после открытия; чтение без браузера не работает, автооткрытия нет |
| Закрытие чата/приложения Codex | Независимый процесс подготовлен; реальная проверка **не проведена** |
| Перезапуск ПК/вход Windows | Автозапуска нет, прежняя задача Disabled; автоматическое восстановление **не реализовано/не проверено** |
| Непрерывность/пропуски | Не обещаются; после переподключения новый baseline, автоматической выгрузки пропусков нет |

Publication time имеет секундную точность: сообщение в неполной первой секунде после baseline может быть отклонено. DOM/сеть/Chrome могут приостановиться во сне, при блокировке или экономии ресурсов. Уменьшение окна/виртуализация может скрыть строки. Пилот не гарантирует полноту потока. Лимит600 секунд заканчивает наблюдение; браузер остаётся доступным пользователю. Не продлевать его автоматически и не ставить Windows task до работающего прототипа и сверки настоящей доставки. Никаких клиентов/администраторов программа не уведомляет.

## Условия доступа

04.11 повторно прочитаны [Telegram Content Licensing](https://telegram.org/tos/content-licensing) и [API Terms](https://core.telegram.org/api/terms). Telegram ограничивает доступ обычным законным предназначенным использованием, отдельно оговаривает допустимые сторонние клиенты и запрещает использование данных для AI без требуемого согласия. Переход к браузеру не отменяет эти ограничения и права авторов; публичность группы или вступление не дают общего разрешения на сбор. Пилот ограничен личным просмотром одной доступной группы, не выгружает историю/участников, не меняет read/online-механику и не передаёт контент в AI. Это технические ограничения, а не заявление о юридическом разрешении всех видов мониторинга. Сохранённые правила группы относятся к прежнему ознакомлению; при изменении условий доступ остановить.

[Рекомендация Chrome](https://developer.chrome.com/blog/remote-debugging-port) требует нестандартный user-data-dir для debugging switches начиная с Chrome136 и рекомендует изоляцию. Использован отдельный профиль с pipe; браузерная сессия остаётся только локально.
