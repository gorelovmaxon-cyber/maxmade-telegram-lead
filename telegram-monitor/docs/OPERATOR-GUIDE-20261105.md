## Команды из папки telegram-monitor

```powershell
.\.venv\Scripts\python.exe automation.py start
.\.venv\Scripts\python.exe automation.py status
.\.venv\Scripts\python.exe automation.py stop
.\.venv\Scripts\python.exe automation.py report
```

Есть Start-monitor.cmd, Monitor-status.cmd и Stop-monitor.cmd. Повторный Start не создаёт второй экземпляр. Stop сохраняет намеренную остановку; контроллер и задача её уважают, включая следующий вход Windows. Возобновление — явный Start. Закрытие браузера вручную может вызвать восстановление; для намеренной остановки используйте Stop.

В status смотреть supervisor_running, host_running, healthy, last_verified_connection, last_web_transport, account_verified, source_verified, last_message_received, delivery_probe, pending_notifications, open_gap, manual_action_required. Сам процесс не означает связь; молчание группы не означает поломку. healthy подтверждает свежий DOM и HEAD веб-узла Telegram, а не MTProto-ack/полноту потока. delivery_probe — последний callback-запрос Bot API, не гарантия следующей отправки.

## Восстановление и автозапуск

Контроллер восстанавливает принадлежащий ему процесс, временный offline и reload той же страницы. Перед новым baseline заново проверяются аккаунт, источник и участие. Стартовое ожидание до 100 секунд; затем задержки 5/15/30/60/120 секунд, максимум пять попыток на разрыв. После пяти минут подтверждённой работы бюджет сбрасывается. Планировщик допускает три перезапуска аварийно завершённого контроллера с интервалом одна минута.

Смена аккаунта/источника, потеря членства и неоднозначные панели останавливают чтение. При login_required самостоятельно войти в отдельном Chrome; после устранения причины ручной паузы — Start. Секреты вводятся только локально. Журнал operations.sqlite3 хранит метаданные проверок/разрывов. Бот сообщает о сбое и восстановлении; при недоступной доставке сведения объединяются после восстановления. Неопределённые отправки uncertain не повторяются вслепую. Три legacy pending вне очереди Chrome; прежние статусы и тихие часы сохранены.

MaxMade-LocalChrome-Reader включён, действие automation.py run, интерактивный пользователь без сохранения пароля Windows. Старый MaxMade-Telegram-Pilot выключен. Однократная установка на другом ПК после восстановления конфигурации, офлайн-тестов и ручного входа в отдельный профиль:

```powershell
.\.venv\Scripts\python.exe chrome_startup.py install
.\.venv\Scripts\python.exe chrome_startup.py enable
.\.venv\Scripts\python.exe automation.py start
```

install выключает задачу; enable разрешает будущие входы. Нужны Python3.12+, Chrome, requirements-client.txt и requirements-browser.txt. Профиль создаёт local_chrome.py open; вход заново. Перед живым запуском другого ПК остановить исходный.

Настоящий вход Windows и закрытие Codex пока не проверены. Выход/reboot без согласования времени не выполнять. После согласованного входа проверить status без Start. Для проверки закрытия чата сравнить время/PID/свежие проверки после самостоятельного закрытия и открытия приложения. Независимая иерархия процесса не подменяет этот опыт.
