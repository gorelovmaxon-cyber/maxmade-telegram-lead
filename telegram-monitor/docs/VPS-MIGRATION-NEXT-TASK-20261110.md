Задание: перенести Telegram-монитор на существующий VPS MAXMADE, сохранив работающий сайт
1. Цель и результат
Разместить Telegram-монитор на постоянно работающем сервере, чтобы ноутбук Максима больше не участвовал в чтении источников и доставке уведомлений.
Первоначально запустить три источника:
- top_ads_freelance;
- freelead;
- biznes_chat.
Сохранить действующий фильтр, профиль MAXMADE, рабочие данные, ручные статусы, бота и получателя.
Для дальнейшего увеличения количества источников выбрать способ чтения, не требующий отдельной вкладки Telegram Web на каждую группу. Нагрузку измерить; не обещать неограниченное количество групп или отсутствие расхода ресурсов.
После настройки монитор должен работать независимо от открытого SSH и Codex. Исполнитель завершает подключение, оставляя службу работать.

Это пример настройки, а не подтверждение наличия ключа maxmade_laptop и разрешённого входа.
Порядок:
1. Проверить существующие настройки и доступные файлы ключей без вывода их содержимого.
2. Не использовать найденный ключ другого проекта только потому, что он существует.
3. Если подходящий ключ найден — сверить назначение и проверить подключение с проверкой ключа сервера.
4. Если ключа нет — создать отдельную пару для этого ПК, предварительно проверив отсутствие файла с таким именем.
5. Публичную часть добавить пользователю maxmade-admin через действующий доступ владельца либо консоль провайдера.
6. Приватный ключ и парольную фразу не передавать в чат.
7. При несовпадении ключа сервера остановить подключение и проверить причину. Не отключать StrictHostKeyChecking ради входа.
Не включать парольный SSH-вход, не менять существующие ключи и не редактировать глобальную SSH-конфигурацию сервера для упрощения доступа.
Если необходимо действие Максима, дать точную инструкцию: где открыть консоль и что добавить. Остальную подготовку продолжать независимо.
4. Что запрещено затрагивать
- Не выключать и не перезагружать сервер.
- Не отключать общую сеть и не проводить испытания общего сетевого сбоя.
- Не останавливать и не перезапускать сайт, Nginx, PHP-FPM или MySQL.
- Не менять DNS, сертификаты, маршруты сайта и конфигурацию reverse proxy.
- Не менять файлы в /srv/maxmade/current и релизах сайта.
- Не читать содержимое приватной конфигурации сайта без необходимости.
- Не менять резервирование сайта.
- Не выполнять общесистемное обновление пакетов.
- Не заменять системные версии зависимостей.
- Не запускать старые deploy-скрипты сайта.
- Не создавать нагрузку, вытесняющую сайт из памяти.
Для монитора использовать отдельные каталог, окружение, данные и службу.

Перед включением доставки отдельно проверить старую очередь:
- что уже отправлено;
- что ожидает;
- что имеет неопределённый результат отправки;
- что устарело.
Не очищать очередь и не отправлять её массово автоматически. Если требуется решение владельца по старым ожидающим карточкам, показать конкретный список без изменения истории.

15. Проверки без отключения сервера

- изолированная имитация недоступности соединения в тестовом процессе;
