## Что делает код

Observer устанавливается в один проверенный корень сообщений. Сначала снимает только исходные ID и время начала, без текстов старой ленты. MutationObserver затем складывает новые видимые добавления/правки в ограниченную очередь. Тексты не отправляются Agent/LLM; нет HTTP-запросов, доступа к browser storage, cookies/auth keys, кликов, логина, вступления, загрузки истории или отправителя. Декоративные время/ответ/кнопки/preview удаляются из текстового фрагмента, автор не выдумывается. Длинный фрагмент ограничен2001 символом до прежней политики ingest.

Новые строки старше baseline/начала наблюдения, дата-разделители, скрытые строки и иной peer игнорируются. Временные дробные и ephemeral IDs отклоняются. По актуальным открытым исходникам WebK data-mid может содержать служебное смещение2^32; оно переводится в исходный ID сообщения для корректного t.me URL. DOM peer супергруппы сверяется с уже закреплённым marked peer из существующего allowlist, новый source_id не создаётся — дедуп остаётся совместимым с прежним адаптером.

BrowserCapture требует внешнюю функцию verify_live, которая должна независимо прочитать проверенные account/source/member из **того же контекста**, и подтверждённый DomContract. По умолчанию selectors_verified=false запрещает установку. Сам код не подменяет эту функцию фиксированным @username. Проверка выполняется до и после чтения очереди, затем прежний ingest/фильтр. Повреждение идентичности, смена URL/корня, переполнение очереди и тайм-аут отключают захват; молчаливое продолжение после потери событий не заявляется. stop останавливает только собственное наблюдение страницы, **не считается подтверждённым завершением оплачиваемой remote-сессии**. Эту часть должен реализовать владелец сессии.

## Фактические проверки

Последний полный прогон с установленным Playwright: **88 tests OK,17.872s** (80 прежних +8 новых browser fixture tests), команда `python -m unittest discover -s tests -q`. Среда проверки — отдельная tools-env переноса с закреплёнными пакетами; исходная .venv монитора не переустанавливалась. В ней Playwright пока отсутствует: новые browser-тесты явно skipped до установки requirements-browser.txt, их skip нельзя объявлять успешной браузерной приёмкой.

Восемь тестов используют настоящий headless Chrome, каждый раз новую изолированную context без профиля/секретов. Страница полностью подставная, выдаётся in-process через перехват Playwright до сети; остальные запросы блокируются. Настоящего Telegram-доступа нет, несмотря на тестовый URL-origin. Проверены:

1. DOM-добавление → извлечение исходного ID → browser_ingest → demand/urgent → monitor.deliver → FakeSink/sent → правка без повторной отправки.
2. Изменение account до чтения очереди: остановка без записи.
3. Повторная старая лента/иной peer не импортируются.
4. Замена корня сообщений отключает наблюдение.
5. Переполнение очереди блокирует приём и не маскируется как нормальная работа.
6. Непроверенный DOM contract не устанавливается.
7. Temp/ephemeral IDs не превращаются в оригиналы.
8. Изменение личности между проверкой и чтением очереди отбрасывает весь batch до записи.

Тихие часы фикстуры отключены только в тестовой Config. Рабочие SQLite, реальные уведомления и настройки не используются тестами. Локальный журнал/хеши и контроль рабочей БД — state/browser-source-20261104.

## Что требуется для живого продолжения

- Выбран по-прежнему @maxmade_pro. Собственный username проверен конечным заданием TinyFish04.11, но это не доказывает личность новой CDP-сессии.
- Нужен самостоятельный владелец подключённой сессии, проверка аккаунта/точной группы/членства и фактических selectors, подтверждение закрытия своей сессии. Нельзя просто выставить selectors_verified=true по фикстуре или историческому Agent-run.
- Доступ к API понадобится только если выбран прямой TinyFish REST/CDP; плагин в чате работает по OAuth и не требует отдельного ключа. Локальный ввод остаётся необязательным, используется текущий bot token. Ротация — отдельное решение после прежнего раскрытия.
- Запрошен режим продолжения: разовая диагностическая сессия до5мин либо пока только offline-подготовка. Оценка по прежнему проверенному контрактному тарифу Browser0.002USD/min — около0.01USD/5мин; это не провайдерский hard spending cap. Реальный финансовый лимит/проверка подтверждённого завершения должны быть определены до старта. До ответа и нужного локального доступа платный запуск запрещён; никакого периодического опроса/повторов по этому выбору нет.
- Затем необходимо настоящее новое естественное событие → observer → ingest/фильтр → уведомление прежнему Максиму, с исходными ID/датой/ссылкой и задержками. FakeSink/тестовая страница/исторический пост это не заменяют. Прямой заказ принимается отдельно, фильтр не ослаблять.

После закрытия чата и reboot постоянное чтение **не работает как готовая функция**: отдельный процесс/Windows task браузерного читателя не реализованы и не включены. Настоящий эксперимент закрытия чата или перезапуска ПК не проводился. Существующая старая задача Disabled; legacy Telethon не запускать автоматически. TG-S17 остаётся открытым.
