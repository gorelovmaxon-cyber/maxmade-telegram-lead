Девять–десять копий Web Telegram заняли около6,62ГБ суммарного working set дерева собственного Chrome в10:50:17 МСК; свободно631МБ из16,04ГБ. В10:42:58 МСК свободно436МБ при19 процессах собственного дерева. Working set может повторно учитывать общие страницы, это не уникально выделенная RAM. Измерения сделаны read-only Toolhelp/PSAPI/GlobalMemoryStatusEx, без чтения командных строк или секретов; остальные программы не закрывались. Низкая память и timeouts совпали по времени, но исключительную причину всех сетевых отказов этим не доказываем.

Простое обновление токена эту нагрузку не устраняет. Перезапуск только собственного читателя09.11 подтвердил восстановление части страниц и новые события v3.1, но не устойчивую работу всех10. Рекомендация для20 источников: подготовить TDLib-прототип одного источника. TDLib — официальный клиентский SDK Telegram с асинхронными updates; он требует api_id/api_hash и собственную авторизацию. Существующие API-настройки локально присутствуют; их корректность для TDLib пока не проверена и значения не выводятся. Нельзя использовать чужие/демонстрационные API-реквизиты или извлекать ключи из Chrome. Локальный номер/код/2FA вводит Максим. Старую сессию сохранять; соединение старого Telethon не запускалось.

Переключение способа чтения ожидает выбора Максима. Текущая система и её ограничения сохраняются до проверенного перехода. Этот документ не утверждает, что TDLib уже установлен, подключён, совместим со всеми источниками или работает после перезапуска Windows.

Условия прототипа после выбора TDLib:

1. Отдельный локальный каталог сессии вне Git; сначала установить библиотеку из проверяемого официального исходника/состава. При сборке учесть доступную RAM, не запускать тяжёлую сборку рядом с перегруженным монитором.
2. Проверить личность @maxmade_pro, тип и членство ранее согласованного top_ads_freelance. Вступления, сообщения клиентам и администраторам не автоматизировать.
3. Один разрешённый источник, изолированная тестовая SQLite и отсутствие реальных отправок на первом шаге. Посторонние чаты не сохранять и не передавать модели. Не использовать Telegram-контент для обучения/улучшения AI.
4. Нормализовать TDLib chat/message IDs к существующим ключам событий, подтвердить совпадение с публичной ссылкой; внутренний TDLib message ID нельзя автоматически считать идентичным browser message_id. Отделить новый update, редакцию, replay и возможное восстановление после паузы. Не импортировать старую историю под видом новых событий.
5. Использовать прежние отбор v3.1, SQLite и единственный delivery/callback worker. Не включать второй потребитель Bot API и не создавать вторую очередь старых карточек. Бот, получатель, owner_status и sent history сохраняются.
6. Измерить RAM, задержки и ошибки на одном источнике и проверить reconnect. Затем доказать новую доставку и поэтапно расширять; лишь после этого уменьшать или выключать браузерные источники. Тихие часы, сетевой uncertain и ручной отклик остаются.
7. Условия Telegram и правила каждой группы действуют и для SDK; смена доступа не создаёт разрешения на запрещённый сбор/рекламу. Общей разрешённости любого мониторинга по наличию SDK не предполагаем.

Источники, проверены09.11.2026:

- [Официальное введение TDLib](https://core.telegram.org/tdlib/getting-started) — клиент, авторизация и updates.
- [Получение API ID](https://core.telegram.org/api/obtaining_api_id) — собственное приложение и API-реквизиты.
- [Условия API Telegram](https://core.telegram.org/api/terms) и [лицензирование контента](https://telegram.org/tos/content-licensing) — действуют независимо от инструмента.
- [Chrome Page Lifecycle](https://developer.chrome.com/docs/web-platform/page-lifecycle-api) — frozen приостанавливает задачи страницы. Усыпление читаемой вкладки нельзя выдавать за продолжающееся DOM-чтение.
- [Playwright routing](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route) — сетевые маршруты не охватывают запросы Service Worker и включение routing отключает HTTP cache. Поэтому блокировку картинок через route нельзя без измерения объявлять безопасным решением памяти Telegram Web; blob/media и кеш приложения требуют отдельной проверки.
