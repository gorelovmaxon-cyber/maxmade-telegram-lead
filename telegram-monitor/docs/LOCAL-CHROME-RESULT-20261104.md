## Длительный запуск подготовлен

`local_chrome.py open` открывает отдельный профиль без чтения. `arm` оставляет ограничение600 секунд. Новый `run`/`auto` выполняет source→проверка собственного Settings и группы→getMe→резервная копия SQLite→захват **без таймера**, до остановки/ошибки guard. Открытие окна само по себе не означает успешный run; смотреть capture_running/account_verified/source_verified.

`chrome_startup.py install` создаёт **новую отдельную задачу MaxMade-LocalChrome-Reader**, по умолчанию Disabled, для текущего интерактивного пользователя Windows с Limited privileges. Старую MaxMade-Telegram-Pilot не включает и не меняет. Задача запускает pythonw/локальный Chrome независимо от Codex, без хранения Windows-пароля. Ручной запуск через Планировщик проверен: чтение и проверка личности активны; цепочка родителей pythonw→pythonw→svchost→services→wininit, Codex/ChatGPT среди родителей нет. После проверки триггер логина вновь отключён; **запущенный reader продолжает работать**.

Это длительный reader с остановкой при ошибке, не доказанная служба24/7. Автоматического переподключения/перезагрузки страницы/открытия закрытого Chrome нет. При offline, смене личности/панели/peer, reload, переполнении или закрытии приём прекращается; требуется явная повторная проверка/auto. На старте Windows задача умеет заново проверить сохранённый вход и создать baseline; настоящий выход/вход Windows и reboot ещё **не проведены**. Работа после реального закрытия приложения Codex ещё **не проверена**: независимая иерархия процессов — только структурное свидетельство.

В длительном режиме возвращён прежний обработчик подписанных callback-кнопок владельца через Bot API getUpdates: проверка owner/chat/signature/ID отправленной карточки остаётся в monitor.handle_callback. Запрос только callback_query, штатный интервал10 секунд, при сетевой ошибке60 секунд; неизвестным пользователям не отвечает и сообщения групп из этого канала не принимает. При существующем webhook запуск останавливается, webhook автоматически не меняется. Это существующий Bot API, без TinyFish Browser/Agent API. Сетевая ошибка не объявляется отзывом token.

Очередь доставки ограничена событиями данного источника с browser-version: новые pending Chrome переживают тихие часы и перезапуск; прежние3 legacy pending не отправляются автоматически. Прежние правила quiet/retry/uncertain/подписей/ручных статусов сохранены. Прерванное sending восстанавливается прежней monitor.recover_interrupted как uncertain и не пересылается вслепую. Перед изменениями при каждом arm/run создаётся согласованная SQLite backup.

Из `D:\привлечение клиентов\telegram-monitor`:

```powershell
.\.venv\Scripts\python.exe local_chrome.py status

Затем проверить две команды status: новая задача/host running, phase=reading,capture_running=true,account/source verified,@maxmade_pro. При потере авторизации вход выполняется только в своём локальном Chrome; после него `local_chrome.py auto`. Номер/код/2FA в чат не передавать. Перезагрузка/выход Windows агентом не выполнялись.
