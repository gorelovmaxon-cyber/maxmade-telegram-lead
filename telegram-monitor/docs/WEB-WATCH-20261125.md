# Веб-мониторинг страниц и снятие Kwork — 25.11.2026

Два изменения в одном выпуске:

1. **Kwork выведен из постоянного поиска.** Парсер и его тесты сохранены,
   но лента больше не опрашивается. Причина: заказы оттуда не окупали отклик.
2. **Добавлен источник `watch`** — страницы без RSS и API через
   changedetection.io. Новый текст со страницы проходит через тот же фильтр,
   дедупликацию, очередь карточек и ИИ-черновики, что и остальные источники.

## Как это устроено

```text
страница ──> changedetection.io ──снимки──> watch_feed.py ──новый текст──>
           (свой таймер)    (REST API)     (сверка строк)      monitor.ingest
                                                                    │
                                              фильтр r11 ──> карточка в Telegram
```

- changedetection.io сам решает, **когда** проверять страницу (его настройка),
  и хранит снимки.
- Наш таймер лент (каждые 10 минут) забирает из его API историю и вытаскивает
  только строки, которых не было в прошлом снимке.
- Сверка идёт **по множеству строк, а не по позициям**: на досках новое
  встаёт сверху и сдвигает остальное, позиционное сравнение выдавало бы
  старые строки за новые.
- Каждый непрерывный кусок нового текста — отдельная заявка. Первое
  включение страницы только запоминает снимок и ничего не присылает.

Источник в базе: `feed:watch`, отображаемое имя «Веб-мониторинг».

## Что имеет смысл мониторить

По убыванию отдачи:

1. Страницы тендеров и закупок без RSS.
2. Разделы «Стать подрядчиком», «Партнёрам», «Для агентств» у студий и
   интеграторов, которые публикуют субподряд.
3. Городские бизнес-порталы, доски объявлений и сообщества без API.
4. Страницы вакансий агентств — **только** если ищете субподряд
   от агентств, а не конечных клиентов.

Не подходит: страницы за логином, страницы с постоянной ротацией блоков
(рекомендации, счётчики, курсы валют) — они дают шум каждые 10 минут.

## Установка changedetection.io на VPS

Служба должна слушать только локальный адрес: API отдаёт содержимое всех
наблюдаемых страниц, наружу его выставлять нельзя.

```bash
# вариант 1: docker
docker run -d --name changedetection \
  -p 127.0.0.1:5000:5000 \
  -v /var/lib/changedetection:/datastore \
  --restart unless-stopped \
  ghcr.io/dgtlmoon/changedetection.io

# вариант 2: без docker, в отдельном venv
python3 -m venv /opt/changedetection/venv
/opt/changedetection/venv/bin/pip install changedetection.io
/opt/changedetection/venv/bin/changedetection.io -d /var/lib/changedetection \
  -h 127.0.0.1 -p 5000
```

Ключ API: `Settings → API` в интерфейсе, скопировать в `MONITOR_WATCH_KEY`.

### Настройки наблюдений

- Интервал проверки: 15–60 минут, не чаще. Каждое наблюдение — это запрос
  к чужому сайту.
- Включить «Ignore text» для дат, счётчиков, «последнее обновление».
- Теги: например `sites` для сайтов и `systems` для систем автоматизации.
  Тогда `MONITOR_WATCH_TAG=sites` ограничивает монитор одной группой.
- Фильтр `xpath` / `css` — снимать только список заказов, без шапки и меню.

## Настройка монитора

В `/etc/maxmade-monitor/monitor.env`:

```text
MONITOR_FEEDS=fl,workspace,connect,watch
MONITOR_WATCH_API=http://127.0.0.1:5000
MONITOR_WATCH_KEY=<ключ из Settings -> API>
MONITOR_WATCH_TAG=
MONITOR_WATCH_MIN_CHARS=40
```

`MONITOR_WATCH_MIN_CHARS` отсекает мелкий шум: короткие блоки короче порога
не становятся заявками.

Применить и проверить:

```bash
sudo systemctl restart maxmade-monitor-bot.service
sudo systemctl start maxmade-monitor-feeds.service
sudo journalctl -u maxmade-monitor-feeds.service -n 30 --no-pager
```

Ожидаемые строки: `kwork: пропущена, отключена 25.11.2026…`,
`watch: свежих N, новых M`.

Ручная проверка без записи в базу:

```bash
cd /opt/maxmade-monitor/current
/opt/maxmade-monitor/venv/bin/python watch_feed.py list   # какие наблюдения видит
/opt/maxmade-monitor/venv/bin/python watch_feed.py dry    # то же, коротко
/opt/maxmade-monitor/venv/bin/python feeds.py dry         # маршруты по всем лентам
```

## Откат

- Только веб-мониторинг: убрать `watch` из `MONITOR_FEEDS`, перезапустить
  бот. Карточки, уже попавшие в базу, остаются.
- Только Kwork: `feeds.py run --only kwork` — разовый прогон без
  возврата в постоянный состав.
- Полный откат фильтра не нужен: изменения не касаются правил отбора.

## Ограничения и правила

- Сбор с чужих сайтов подчиняется правилам этих сайтов. hh.ru, designer.ru
  и подобные запрещают автоматизированный сбор — мониторить их нельзя,
  даже готовым инструментом.
- Не ставить интервал чаще 15 минут и не добавлять десятки наблюдений
  сразу: это нагрузка на чужой сайт и повод для блокировки по IP.
- Сообщения и страницы могут содержать персональные данные; срок хранения
  в базе — 30 дней (`MONITOR_RETENTION_DAYS`).
- Текст снимка обрезается до 4000 знаков на блок и до 2000 при приёме —
  длинные страницы дадут усечённую заявку.
