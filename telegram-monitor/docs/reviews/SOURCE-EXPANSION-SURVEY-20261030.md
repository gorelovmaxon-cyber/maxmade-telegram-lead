## Условия чтения и доступа

1. [Bots FAQ](https://core.telegram.org/bots/faq): бот получает сообщения каналов, где состоит; публичная ссылка не добавляет бота в канал. Для выбранного канала требуется действие администратора, минимальные необходимые права, затем проверка Bot API на новом разрешённом событии.
2. [API Terms §3.3](https://core.telegram.org/api/terms): клиент приложения, открывающий контент каналов, должен поддерживать official sponsored messages. Текущий reader намеренно проверяет `megagroup` и не является готовым адаптером каналов. Нельзя просто снять проверку и объявить доступ допустимым.
3. API требует собственного `api_id` и соблюдения условий использования. Старое рабочее членство в группе не доказывает разрешение читать/хранить другой источник. Подключение новых каналов клиентским аккаунтом без отдельного решения не выполнялось.
4. Ссылка «правила» в подвале zakaz_design ведёт на [пост /4409](https://t.me/zakaz_design/4409) об антифрод-боте и жалобах. Она **не является** установленным разрешением автоматического чтения или тарифами отклика. Запрет или разрешение автоматического чтения из этого текста не выводится.
5. Разовый просмотр публичной страницы не означает, что разрешён постоянный web-сборщик. Такой адаптер не выбран и не запускается. Боты размещения объявлений не являются подтверждёнными API чтения и им не отправлялся /start.
