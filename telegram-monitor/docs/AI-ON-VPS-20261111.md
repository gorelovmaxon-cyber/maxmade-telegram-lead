# Модель на VPS: включение и расходы

Документ относится к модулю `ai_assist.py` (необязательный) и `site_audit.py`
(не требует ничего, работает без ключей). Ни одна часть не отправляет сообщений:
модель только дописывает к карточке вердикт, черновик и краткий осмотр сайта.

## Что уже работает без модели

- Отбор заказов по правилам v3.3 (роли, бизнес-адаптер, политика уведомлений).
- Кнопки: `Взял` / `Не подходит` / `Ответил` и `Диалог` / `Договорились`.
- Строка «Как связаться»: `@ник в боте` / `@ник, писать в личку` / хост ссылки.
- Отчёт `monitor.py report`: воронка по источникам и медиана от публикации
  до карточки (медиана, а не среднее — одна задержавшаяся карточка не искажает картину).
  Сам приходит в понедельник с 10:00 один раз в неделю; вручную — той же командой.
- Осмотр сайта клиента: выполняется локально, один GET, без ключей и без модели.
  Готовится воркером вместе с ИИ-блоком.

## Что даёт модель

- `ИИ-проверка` — второй проход по спорным карточкам: `подходит` / `спорно` /
  `не подходит`. С `MONITOR_AI_STRICT=1` модель способна отклонить и явную карточку.
- `Черновик` — 3–5 предложений от первого лица, без ссылок и без выдуманных цифр.
- `Сайт клиента` — короткая строка «что видно на главной» для разговора.

Перед отправкой в модель текст очищается: удаляются все URL, `@никнеймы`, почты
и телефоны (`ai_assist.scrub`). Модель ничего не знает о том, кому писать.

## Модель и порядок цен

По умолчанию `MONITOR_AI_MODEL=claude-opus-5-5`.

Одна карточка — это один или два вызова:

| Вызов | Когда | Токенов примерно |
|---|---|---:|
| `judge` (effort=low) | спорная карточка, или каждая при `MONITOR_AI_STRICT=1` | вход ~700, выход ~120 |
| `draft` (effort=medium) | явный заказ | вход ~1 300, выход ~350 |

Порядок величины при 100 карточках в месяц: ~70 вызовов `judge` и ~100 `draft`.
Точную сумму в рублях считать по действующему прайсу Anthropic; сам монитор
считает только число вызовов (`monitor.py report`, строка «Вызовов ИИ за месяц»).

Можно разделить модели: `MONITOR_AI_MODEL` для черновиков и
`MONITOR_AI_MODEL_JUDGE` для проверки. Результат кэшируется навсегда по паре
`(кандидат, версия текста)`: повторный прогон не тратит деньги.

### Временные сбои и повторы

Кэш навсегда относится только к **окончательному** ответу. Если вызов упал по
временной причине — таймаут, `429`, обрыв соединения, перегрузка — это не
считается ответом: при следующем проходе карточка будет обработана заново.
Иначе одна сетевая просадка навсегда лишала бы карточку ИИ-блока.

Повторы ограничены тремя попытками (`ATTEMPT_LIMIT` в `ai_assist.py`), чтобы
сбойный ключ не выжег месячный бюджет на одной карточке. Счётчик хранится в
`ai_reviews.attempts`; после третьей неудачи карточка показывается с ошибкой
(`Сайт клиента: проверить вручную`), а вызовы по ней прекращаются до смены
текста заказа.

Окончательные ошибки (некорректный JSON, пустой черновик, отказ модели) в кэш
попадают сразу и повторно денег не тратят.

Таймаут одного вызова — 90 с. Реальные замеры 12.11.2026: `judge` ~7.7 с,
`draft` ~12.3 с; 45 с не хватало при сетевых просадках.

## Включение — вручную

Скрипт установки я не создавал (серверная установка требует вашего решения).
Шаги выполняются на VPS под `maxmade-admin`; сайт, nginx, php-fpm, mysql и
`/srv/maxmade/current` не затрагиваются.

1. Резервная копия окружения:

   ```sh
   cp -a /etc/maxmade-monitor/monitor.env /etc/maxmade-monitor/monitor.env.bak-ai
   ```

2. Добавить строки в `/etc/maxmade-monitor/monitor.env`. Ключ вводите сами в
   редакторе, не в чате и не в этой инструкции:

   ```sh
   MONITOR_AI_ENABLED=1
   MONITOR_AI_API_KEY=<вставить ключ вручную>
   MONITOR_AI_MODE=full                     # полный разбор каждой прошедшей карточки
   MONITOR_AI_MODEL=claude-opus-5-5         # черновик
   MONITOR_AI_MODEL_JUDGE=claude-sonnet-5-5 # вердикт (вдвое дешевле)
   MONITOR_AI_HOLD_MINUTES=5                # сколько ждать блок, прежде чем отправить без него
   MONITOR_AI_MONTHLY_CALLS=1500
   # MONITOR_AI_STRICT=1   # разрешить модели ОТБРАСЫВАТЬ карточку, а не только помечать
   ```

   ### Режимы

   `MONITOR_AI_MODE=draft` — черновик на каждую карточку, прошедшую правила.
   Этот режим даёт один текстовый запрос к модели на успешную карточку и
   оставляет решение об отборе правилам.

   `MONITOR_AI_MODE=grey` (по умолчанию) — модель проверяет только спорные типы,
   явным заказам пишет черновик.
   `MONITOR_AI_MODE=full` — каждая карточка, прошедшая правила, получает всё сразу:
   вердикт, осмотр сайта, черновик. Это и есть «фильтр отсеивает, ИИ разбирает
   оставшееся».

   В `full` вердикт `not_fit` **только помечает** карточку. Убрать её может лишь
   `MONITOR_AI_STRICT=1`. Правила уже отсеивают 91%, и дополнительная потеря
   живого заказа стоит дороже одной лишней карточки.

   ### Задержка отправки

   Карточка создаётся сразу готовой к отправке, а воркер ходит по таймеру раз в
   3 минуты. Без удержания модель всегда проигрывала гонку и блок не попадал в
   карточку. Поэтому карточка ждёт свой блок, но не дольше `MONITOR_AI_HOLD_MINUTES`:
   потом уходит без него. Опоздавший заказ стоит дороже карточки без черновика.

3. Поставить пакет в venv монитора (не в системный Python):

   ```sh
   /opt/maxmade-monitor/venv/bin/pip install -r /opt/maxmade-monitor/current/requirements-ai.txt
   ```

4. Установить юниты из `transfer/systemd/` рядом с остальными:

   ```sh
   sudo install -m 0644 -o root -g root \
     maxmade-monitor-ai.service maxmade-monitor-ai.timer /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now maxmade-monitor-ai.timer
   ```

5. Один пробный прогон вручную, до таймера:

   ```sh
   sudo systemctl start maxmade-monitor-ai.service
   journalctl -u maxmade-monitor-ai -n 20 --no-pager -o cat
   ```

   В логе должно быть `{"judged": N, "drafted": M, ...}`. Если `errors` растёт —
   проверить ключ и лимит, не оставляя таймер включённым.

6. Перезапустить только бота (карточки читают кэш):

   ```sh
   sudo systemctl restart maxmade-monitor-bot
   ```

Откат:

```sh
sudo systemctl disable --now maxmade-monitor-ai.timer
cp -a /etc/maxmade-monitor/monitor.env.bak-ai /etc/maxmade-monitor/monitor.env
sudo systemctl restart maxmade-monitor-bot
```

После откатa карточки показываются как раньше: `ai_assist.configured()` вернёт
ложь, блок просто не добавляется.

## Как устроен «только подходящие заказы»

1. Правила v3.3 отсеивают явный мусор, вакансии и чужие предложения услуг.
2. Спорные карточки (`ambiguous`, `offer`, `other`, `partnership`, `vacancy`)
   уходят в `judge`. Вердикт `not_fit` переводит карточку в `rejected`: она
   остаётся в базе и видна в отчёте, но не приходит в Telegram.
3. С `MONITOR_AI_STRICT=1` такая проверка выполняется и для явных заказов.
   По умолчанию выключена: ошибочный отказ дороже лишней карточки.
4. Как только карточка доставлена или получила ваш статус, воркер её не трогает.
5. Бюджет (`MONITOR_AI_MONTHLY_CALLS`) останавливает вызовы; карточки при этом
   продолжают приходить без ИИ-блока.

## Ограничения, которые надо знать

- Вердикт модели — подсказка, а не решение. Статус меняете вы кнопками.
- Сайт осматривается один раз, только главная, только публичное. `robots.txt`
  не запрашивается — это осознанное упрощение; расширять до обхода не планируется.
- Если сайт за Cloudflare/JS-рендером, осмотр даст пустой результат — карточка
  покажет «проверить вручную».
- Модель может ошибаться в оценке бюджета и сроков: черновик не содержит цены
  и срока специально.
